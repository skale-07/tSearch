## What it is

Unseen-talent discovery. Olympiad/named seeds are resolved to LinkedIn
identities (headed Playwright + cookies), enriched from personal websites,
expanded one hop through their real GitHub collaboration graph (collaborators,
followers) and Substack, scored on builder/thinker/pedigree evidence, and
inspected on a radial-tree UI. Rubric-driven LLM judges then assess frozen
candidates' public work into a `priority_score`, and a recruiter digest is
emailed via Resend with reviewer feedback looping back into ranking.

```text
login (cookies) → resolve LinkedIn + websites → expand GitHub/Substack (hop-1)
    → optional hop-2 branch expand (UI) → score → candidates.json + profiles/
    → assessment judges (frozen input) → digest email → reviewer feedback
```

## Load-bearing invariants

- **Discovery / assessment separation:** assessment reads frozen
  `output/candidates.json` only; never re-runs discovery or fixes identity.
  `final_score` (discovery) and `priority_score` (assessment) are never
  collapsed into one number. Reviewer feedback reorders digests but never
  rewrites `priority_score`.
- **Evidence-grounded judging:** missing evidence maps to
  `insufficient_public_evidence`, never a negative judgment; ownership share
  is omitted (not fabricated) when no unfiltered repo commit sample exists.
- **No PII in git:** `profiles/`, `backup/`, `data/`, `cache/`,
  `output/`, `cookies.json`, `.env` are gitignored. The repo is public.
- **Fail-closed side effects:** `digest:send` defaults to `--dry-run`;
  tests/iteration use `ASSESSMENT_MOCK_LLM=1`; LinkedIn scraping is paced
  (`LINKEDIN_DELAY_MS`), cached, and fails loudly on session expiry
  (`LinkedInAuthError`) rather than emitting garbage.

## Data stores (all gitignored, filesystem JSON — no database)

- `output/candidates.json` — frozen discovery output; assessment's only input
- `profiles/<seed>/…` — per-seed tree profiles feeding the UI
- `data/people/<slug>.json` — cross-run per-person records (score history, graph, freshness)
- `data/feedback/<candidate_id>.json` — reviewer verdicts (relevant / not_relevant / explore_network)
- `cache/{github,linkedin-search,linkedin-profile-v2,substack}/` — TTL'd fetch cache (`FORCE_REFRESH=1` bypasses once)
- `output/assessment-runs/<id>/` — assessment records + digest artifacts
